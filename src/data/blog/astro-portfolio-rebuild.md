个人网站很容易成为“什么都有，但找不到重点”的集合。这次重构从访客任务出发：先看清身份与方向，再进入项目证据和技术文章。

## 为什么选择静态架构

项目和文章是站点的核心，它们在发布后不需要服务端个性化。静态生成能在构建时完成数据验证、路由生成与搜索索引，客户端只保留主题、菜单、筛选等必要交互。

### 内容契约先于页面

项目 schema 明确要求封面、技术栈和日期，可选外链缺失时页面不渲染死链接。

```ts
const published = entries
  .filter(({ data }) => !data.draft)
  .sort((a, b) => b.data.pubDate.getTime() - a.data.pubDate.getTime())
```

### 渐进增强保留底线

项目筛选在 JavaScript 可用时更新列表；禁用脚本时，所有项目仍然可见。搜索索引如果在开发环境不存在，页面会给出博客和项目入口，而不是空白。

## 完成标准

重构不以“页面看起来完成”为终点。内容契约、键盘路径、移动布局、搜索索引与部署产物都需要有可重复的验证证据。
